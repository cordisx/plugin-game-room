# Game interface design

Apply when designing or revising game-room plugin pages.

- Keep the Codex shell, typography, theme tokens, compact spacing and public controls consistent. Game identity belongs in plugin content, not replacement chrome.
- Prefer flat Codex-style presentation: avatars, restrained color fields, clear selected states and outline icons. Skeuomorphic materials and dimensional character stages are not required for game identity.
- Express game character through selection, participation and dispatch: selecting a companion and destination should have clear visual hierarchy and selection feedback. Avoid generic administration tables as the default composition.
- Use depth, modest overlap and a distinct focal point purposefully. Do not equate game design with oversized character art, metallic frames, glowing pedestals or a full-screen wallpaper.
- Design around existing components and independently placeable assets. Do not rely on seamless joins between AI-generated artwork and CSS backgrounds. Arbitrary Agent avatars and user-defined games must remain visually complete without bespoke illustrations.
- Keep initial text density low; primary actions may have short labels, secondary actions use square icon buttons with accessible names. Preserve essential action terms before confirmation.
- Evaluate real content, narrow layouts, light/dark contrast and scrolling during implementation. Image mockups communicate direction, not proof that assets, interactions or responsive layouts work.
- Prefer a runnable prototype built from real components for layout decisions. Generate imagery only for a bounded visual need; distinguish illustrative placeholders from available product capabilities.
