# Token 抵押对局

2026-09-16 实现候选：经济插件奖池账本、公开 Host 桥接、游戏服务、客户端及多轮规则已接入并通过隔离测试。已通过独立 Native 实例的德州两手衔接、居中布局及五子棋电脑应手、悔棋和退出验证；尚未切换原钱包或线上部署。资金链路的证据来自隔离账本、真实 Host IPC 和 Workers 测试，不代表原账户的 Native 资金验收。现有线上版本不会因本分支改动自动切换。

## 游戏产品规则

所有 Token 对局均为参与者实际抵押的已有 Token 之间转移。游戏服务只确定规则结果和分配比例；原有本地经济插件持有余额、冻结本金、写入收支并执行结算。模型用量仍是新币的唯一发行来源。支付、退款与中奖转入在账本中分开记录。

创建房间展示每位玩家抵押额和玩法的分配规则；最大人数仍是容量上限。已入座玩家达到玩法最低人数、准备完成且抵押成功后即可开始，无需坐满。

五子棋等单局胜负玩法：按规则声明的胜者权重分配奖池；无胜者的平局按原抵押退款。允许不同游戏声明多个胜者及比例。游戏自报金额不构成直接写入钱包的权限。

德州：创建时设置固定总手数。一手结束只结算局内筹码，不关闭整场牌局、不重复收取抵押、不重置筹码；进入下一手时保留筹码、轮换庄位、重新洗牌。达到总手数，或剩余可参与玩家不足最低人数时结束整场，并按剩余筹码占比分配抵押 Token。

德州退出：在手间按已经结算的剩余筹码兑回 Token；进行中的退出请求先标记离桌并按规则弃牌，待本手底池及边池完成分配后进行兑回，禁止带走尚未结算的下注。超时、断线不等于自动提现。退出签收、下一手推进、房间关闭要进行版本检查，避免同一笔筹码被重复提现和投入。

抵押局里的规则电脑必须有实际出资方，不能生成无抵押筹码后兑换 Token。本期规则电脑仅参与积分局，不为电脑生成可兑回资产。拥有真实已授权钱包的 Agent 可以正常抵押；观战不抵押。

## 经济与公共能力变更范围

现有 `wallet-spend/v1` 仅支持同一本金的消费和退回，不能承载胜者收到他人抵押。不能修改它的既有语义、伪造用量收入、重开旧远程经济服务或直接写余额来实现本功能。

需要 Protocol、Host、经济插件一起增加版本化公共奖池能力：

- 不可变条款绑定服务公钥、整场牌局身份、确切游戏包、轮数、规则、每名玩家的钱包与出资份额。
- 本地授权后冻结实际本金，钱包签署唯一抵押凭据。服务验证全部凭据后才开放 Token 对局。
- 结算绑定同一组抵押、服务的最终结果、整场或退出序号、完整分配向量以及前序结算。经济插件验证证明和总额守恒，并原子写入借贷账目和收据。
- 不允许仅凭赢家客户端提交的余额或游戏 JavaScript 指定的金额记账。跨钱包转入必须有可验证的来源本金和唯一归属，不能重复使用同一抵押证明。
- 部分退出后，累计兑回加剩余托管必须等于最初抵押；整数余数在确定顺序中分配，不能每次独立四舍五入。
- 网络中断、重复请求、钱包离线和服务重启都重用同一操作编号。提交结果不明时查询原操作，不另建发币或退款操作。
- 历史席位费、旧抵押与旧账本不追溯转换成新奖池；在途旧交易沿原协议恢复。新房间仅在公共奖池能力端到端可用后切换。

## 落地及验证顺序

1. 公共契约和 Host 可信桥接；本地经济插件证明验证、守恒和幂等账目。
2. 游戏服务抵押、奖池、退出结算、断线恢复与持久化；各游戏只输出规则结果。
3. 德州多手状态机、固定手数、筹码延续、离桌与结算界面；五子棋接入同一结算入口。
4. 两个独立钱包实测一胜一负、平局、退款、重复结算、篡改证明与离线恢复。德州测试边池、零筹码、中途退出、手数边界和服务器重启。
5. Native 完整对局与原始本地账本核对通过后，发布匹配的公共能力及后端版本。

## 实现边界

新交易使用 `economy.pool-terms/v1`、`economy.pool-reservation/v1` 和 `economy.pool-decision/v1`。Host 暴露可选 `walletSpend.pool`；旧消费 API 不变。客户端同时检查 Host 与来源的奖池声明，缺少时不发起新抵押。

经济插件数据库升级到版本 3，`poolClearing` 记录跨钱包转入与转出，原用量发行量不增加。升级前备份原数据库；发生奖池结算后不能让版本 2 的服务重新写入该库。经济服务必须作为唯一写入版本切换，不能覆盖原密钥、账户或用量进度。

游戏服务使用 `SPEND_TRUSTED_WALLET_KEYS`（JSON 公钥数组）登记经济回执权威。默认空列表不开放新奖池；普通游戏账户绑定不能自行取得权威资格。历史回执仍可恢复。密钥登记是信任一个经济插件部署，不是对可由本机所有者篡改的数据库提供远程硬件证明，不能宣称防止可信权威回滚或作恶。生产登记必须来自实际配置的经济插件，不能采用客户端声明的公钥作为准入来源。

德州以 1 筹码对应 1 Token，退出向量为累计最终兑回额，离开者金额不可更改。后续钱包按序补齐决议；游戏服务不保管用户余额。进行中的奖池不允许房主直接关闭并退款，玩家通过离桌操作退出；最终结果完成后可以关闭房间。

五子棋默认 3 局，德州默认 10 手，均可配置。五子棋累计胜局，整场最高分胜者平分奖池，全平退回本金；主动退出按认输处理。旧不可变游戏包与其展示兼容文件保持原样。

SDK `allocateTokenPool` 仅负责整数分配，资金校验和写账仍在经济插件。隔离测试不代表 Native、正式发布或用户验收。

## 候选验证与依赖

本候选的客户端与服务端使用 `sdk/experimental/*token-pool-r46.tgz` 配套包，锁文件固定其完整性；这些是实验构建，不是已发布的公共 SDK 版本。Protocol、Host 和经济插件仍需按正式跨仓库流程合入后替换依赖。

独立 Native 测试使用临时游戏数据库及正式 provision 的 Codex 账户信任，不连接原经济账本。德州 8 人上限、2 人开局，第一手后筹码从 1000/1000 变为 980/1020，第二手延续筹码并轮换庄位；三种阶段牌桌坐标完全一致。五子棋电脑应手后悔棋将双方本轮落子撤回，进行中退出返回大厅。
